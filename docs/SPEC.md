## 1. Общие сведения

| Параметр | Значение |
|---|---|
| Наименование | Сайт агентства недвижимости DUNE |
| Домен | `dunestate.ru` |
| Заказчик | Агентство недвижимости DUNE (г. Грозный) |
| Версия задания | v1 |
| Референсы UX/тональности | etagi.com, vladis.ru |

**Краткое описание.** Премиальный сайт-витрина агентства недвижимости с удобным поиском по четырём
направлениям продаж: **Новостройки** и **Вторичка** (Россия), **Дубай** (ОАЭ),
**Саудовская Аравия**. Публичная часть — каталог и заявки; закрытая часть — админка для управления
объектами, контентом главной, заявками и настройками. Личных кабинетов покупателей нет: избранное
хранится в браузере, контакт с клиентом начинается с заявки.

### 1.1 Термины

- **Направление** — одна из четырёх категорий продаж: `NEW` (Новостройки РФ), `RESALE` (Вторичка РФ),
  `DUBAI` (ОАЭ), `SAUDI` (Саудовская Аравия).
- **Объект** — единица недвижимости (`Property`): квартира, дом, таунхаус, коммерция, участок.
- **Лид (заявка)** — обращение посетителя через форму (`Lead`).
- **Сайтовый слой** — редактируемые на сайте поля объекта (slug/SEO, подборки, бейджи, премиум-тон),
  переживающие синхронизацию с CRM.
- **QuickDeal** — внешняя CRM, источник объектов и менеджеров; сайт работает как её зеркало.
- **DoD** (Definition of Done) — критерий готовности этапа.

## 2. Цели и назначение

1. Дать заказчику премиальную витрину для четырёх направлений с удобным поиском и SEO-индексацией.
2. Обеспечить поток заявок: мгновенное сохранение в БД, уведомление менеджеров в Telegram, задел под Bitrix24.
3. Снять с заказчика ручное ведение объектов: автоматическое зеркалирование инвентаря из CRM QuickDeal.
4. Дать единую админку под один аккаунт для управления объектами, контентом главной, заявками и настройками.
5. Корректно показывать мультивалютные цены по направлению с автообновляемым курсом ЦБ РФ.

## 5. Ключевые продуктовые решения (контракт по объёму)

### 5.1 Источник объектов — QuickDeal (зеркало)

- Объекты и менеджеры ведутся в CRM QuickDeal; сайт — зеркало через её **родной фид**
  (`/api/v6/feed/organisationObjects/{org}?format=quickDeal`). Не Яндекс-фид: тот теряет
  направление, `$`-цену, рассрочку, назначение земли, статус проекта.
- **Строгое зеркало:** поля из фида — read-only на сайте. Редактируемый сайтовый слой
  (`slug`/SEO, выбор в подборки главной, `badges`, премиум-кураторство, `placeholderTone`)
  переживает синхронизацию.
- Импортируются только объекты с `isSendToCompanySite` / `export=companySite`. Частота ~1 час.
- Идентичность: `externalId = feedId` (`QD_RS_*`), `source`, `syncedAt`.
  `status=sold` → на сайте «Продано» (страница живёт); пропал из фида → `ARCHIVED`. Страница объекта живёт всегда (SEO).
- Маппинг направления: `RU` + «Квартира в новостройке» → `NEW`; `RU` + прочее → `RESALE`;
  `AE` → `DUBAI`; `SA` → `SAUDI`.

### 5.2 Типы объектов

- Набор: **Квартира, Дом (вкл. Коттедж), Таунхаус, Коммерция, Участок** —
  `APARTMENT, HOUSE, TOWNHOUSE, COMMERCIAL, LAND`.
- **Студия — не тип, а значение «комнат»** у квартир (`rooms=0`). Фильтр комнат жилья начинается со «Студии».
- `VILLA`/`STUDIO` из enum убраны, `PENTHOUSE` не вводится (нет в инвентаре).
- Категорийные фильтры: жильё (комнаты/этаж/площадь/срок сдачи/рассрочка/новостройка),
  участок (площадь в сотках/га, назначение земли, коммуникации, рассрочка),
  коммерция (площадь, вид помещения, этаж/этажность, рассрочка).

### 5.3 Валюта и конвертация (§5)

| Направление | Базовая валюта хранения | Отображение |
|---|---|---|
| Новостройки (РФ) | `RUB` | `₽` |
| Вторичка (РФ) | `RUB` | `₽` |
| Дубай (ОАЭ) | `USD` | `$` + `AED` + `₽` |
| Саудовская Аравия | `USD` | `$` + `SAR` + `₽` |

- Хранится одна цена в базовой валюте; конвертации — только для отображения.
- `AED`/`SAR` привязаны к доллару фиксированными константами: `USD→AED ≈ 3.6725`, `USD→SAR ≈ 3.75`.
- `USD→RUB` = курс ЦБ РФ (тянется ежедневно) + надбавка из настроек (по умолчанию +2 ₽).
- Нет свежего курса → последнее известное со знаком `≈`; полный холодный старт → `₽` скрыт.
  Округление `₽` крупное (до 100 тыс.), со знаком `≈`. Цена 0 → «по запросу».
- Локальная валюта показывается только в своём направлении (AED — Дубай, SAR — Саудовская).
- Фильтр цены — в валюте выбранного направления; каталог всегда привязан к одному направлению.

### 5.4 Заявки и менеджер (§7)

- v1: БД + Telegram (лид сперва в БД, экран успеха сразу, Telegram фоном с флагом/ретраем).
  Bitrix24 — позже, за флагом, по доступам.
- Антиспам: honeypot + щедрый rate-limit по IP (~10/час), без капчи.
- Согласие 152-ФЗ обязательно (`consentAt`); без согласия — блок на фронте и 4xx на бэкенде.
- Менеджер: персональный из `assigned` фида; фолбэк — общий контакт компании / активный менеджер направления.
- Подборки главной: пропавший/проданный объект тихо скрываем, добираем следующим.

## 6. Функциональные требования и модель данных

### 6.1 Модель данных (§11)

- **`Property`** (расширение): `lat Float?`, `lng Float?`; поля синхронизации `externalId` (уникальный,
  nullable для сайтовых), `source` (`QUICKDEAL | SITE`), `syncedAt`; тип-специфичные `landUse?`,
  `utilities String[]` (участок), `commercialKind?` (коммерция); менеджер объекта `managerName?`,
  `managerPhone?`, `managerPhotoUrl?`.
- **`PropertyType` enum**: `APARTMENT, HOUSE, TOWNHOUSE, COMMERCIAL, LAND`.
- **`Lead`**: контакт (имя, телефон, опц. e-mail, комментарий), `source`, `propertyId?`, `direction?`,
  `status` (`NEW | IN_PROGRESS | DONE | SPAM`), `consentAt` (обязательно при создании), таймстемпы,
  флаги доставки (Telegram/Bitrix24).
- **`Manager`** (по направлению): `direction`, имя, фото, телефон/контакт; одна активная запись на направление.
- **`SiteSettings`** (singleton): Telegram token + chat id, Bitrix24 webhook URL + enabled-флаг,
  надбавка USD→₽ (по умолчанию +2 ₽), общий контакт компании, ключ Яндекс.Карт.
- **`HomeContent`**: плоский набор полей под фиксированные секции главной.
- **`FxRate`** (кеш курса): база/котировка, значение, источник, время обновления.

Все изменения схемы — декларативно в `schema.prisma`, миграции штатным воркфлоу (SQL руками не писать).

### 6.2 Бэкенд (§5, §7, §10)

- **Валютный слой:** константы AED/SAR; курс ЦБ РФ + надбавка → `USD→RUB`; кеш `FxRate` с фолбэком на
  последнее значение; ежедневный cron `fx:refresh`; функция конвертации отдаёт релевантный набор по направлению.
- **Роуты лидов:** публичный `POST /api/leads` (валидация контракта, обязательная проверка согласия,
  honeypot, rate-limit по IP, дедуп по `(телефон, объект)` ~10 мин); Telegram-нотификатор (фон + ретрай + флаг);
  Bitrix24-адаптер за флагом; маршрутизация на менеджера объекта; админ-роуты (список/фильтр/смена статуса).
- **Менеджеры/настройки/контент:** CRUD `Manager` по направлению + публичная отдача; CRUD `SiteSettings`
  (+ публичная проекция без секретов); CRUD `HomeContent` + публичная отдача. Все админ-роуты под `require-auth`.
- **Импорт QuickDeal:** клиент чтения родного фида (секрет в env `QUICKDEAL_FEED_*`); маппинг фид→`Property`;
  upsert по `externalId`; `sold`→`SOLD`, отсутствие в фиде→`ARCHIVED`; cron ежечасной синхронизации
  `quickdeal:sync` с устойчивостью к недоступности; синхронизация не затирает сайтовый слой.

### 6.3 Website — публичная витрина (§6, §8, §9)

- **Главная (фиксированные секции из `HomeContent`):** Hero (варианты композиции), умный поиск (табы по
  4 направлениям → каталог с предзаполненными фильтрами), плитки направлений, подборка объектов с табами,
  блок рассрочки с калькулятором для новостроек, форма заявки с экраном успеха, футер. Пустые/дефолтные
  состояния при незаданном контенте.
- **Каталог:** фильтры (направление, тип, комнаты, цена в валюте направления, площадь,
  рассрочка/премиум/новостройки), сортировка, пилюли-чипы, счётчик, пустое состояние; предзаполнение по
  ссылкам с главной; кнопка «Показать ещё» (инкремент `page`, аккумуляция); всегда одно направление
  (single-select, по умолчанию «Новостройки»); мультивалютные цены по направлению.
- **Карточка объекта:** галерея, ключевые характеристики, описание + «что входит», цена с рассрочкой и
  мультивалютой, карта с точной точкой (Яндекс.Карты, бесключевой map-widget по `lat/lng`), карточка
  менеджера направления, похожие объекты, форма заявки (передаёт `propertyId`/`direction`, чекбокс согласия).
- **Избранное:** локально в `localStorage`, без аккаунтов; индикация и список; переживает перезагрузку.

### 6.4 Webapp — админка (§10)

- **Доступ:** экран логина (логин/пароль) поверх существующей аутентификации; единый auth-гейт в `AdminShell`,
  без публичной регистрации.
- **Объекты:** CRUD, статус публикации (DRAFT/PUBLISHED/ARCHIVED/SOLD), цена (валюта из направления);
  QuickDeal-зеркала редактируются только в сайтовом слое (`source` неизменяем); загрузка фото (пресайн
  `POST /api/admin/uploads` + PUT, плюс вставка ссылок); карта-пикер координат (Яндекс.Карты JS API при
  заданном ключе, иначе бесключевое превью); бейджи, фичи, флаги, тип-специфичные поля с очисткой при смене типа.
- **Контент главной:** редактор текстов hero и выбора объектов фиксированных секций. Редактирование плиток
  направлений — вне v1 (плитки фиксированы).
- **Заявки:** список лидов, фильтр по статусу, смена статуса (вкл. ручной `SPAM`), маркер доставки в Telegram.
- **Настройки:** менеджеры по направлениям; Telegram (token + chat id); Bitrix24 (webhook URL + флаг);
  Яндекс.Карты (JS API-ключ); надбавка к курсу (валидация значения).

## 7. Этапы работ и критерии готовности

### Этап 1 — Данные и контракты
Расширение `Property`; модели `Lead`, `Manager`, `SiteSettings`/`HomeContent`, `FxRate`; контракты;
миграции + Prisma-клиент; сид демо-данными по 4 направлениям и всем типам; контрактные тесты.
**DoD:** миграции применяются на чистой БД; `prisma generate` зелёный; сид наполняет 4 направления и новые
типы; контрактные тесты проходят; типы доступны бэкенду и фронтам.

### Этап 2 — Бэкенд
Валютный слой; роуты лидов с доставкой; роуты менеджеров/настроек/контента; импорт из QuickDeal.
**DoD:** лид с согласием создаётся, попадает в БД и Telegram; без согласия — 4xx; honeypot/rate-limit
срабатывают; валютный слой отдаёт корректный набор по направлению с фолбэком; менеджеры/настройки/контент
читаются и пишутся через защищённые роуты; интеграционные тесты зелёные.

### Этап 3 — Website (Astro)
Главная (фикс. секции), каталог («Показать ещё», фильтры по валюте, мультивалюта), карточка (галерея, карта,
менеджер, похожие, форма), избранное.
**DoD:** главная/каталог/карточка совпадают с прототипом; переход с главной в каталог работает с фильтрами;
«Показать ещё» подгружает порциями; мультивалюта корректна; карта показывает точную точку; заявка с согласием
уходит и подтверждается экраном успеха; избранное переживает перезагрузку.

### Этап 4 — Webapp (админка)
Логин и auth-гейт; CRUD объектов с фото и картой-пикером; редактор контента главной; список заявок;
настройки.
**DoD:** под логином доступны объекты/контент/заявки/настройки; объект можно создать, проставить координаты
пикером, загрузить фото и опубликовать; контент главной редактируется и виден на витрине; лиды видны и меняют
статус; настройки сохраняются и влияют на доставку/курс.

### Этап 5 — Валидация и QA (§13.5)
E2E критичных путей (создание/публикация объекта → виден на витрине; заявка с согласием → БД + экран успеха;
блок без согласия; фильтры каталога и счётчик; переход с главной в каталог); контрактные/интеграционные тесты
лидов и валютного слоя; визуальная сверка с `design-reference/`.
**DoD:** E2E-спеки написаны и подключены к харнессу; контрактные/интеграционные тесты лидов и валютного слоя
проходят; визуальная сверка без расхождений на критичных экранах.

> Прим.: Playwright-харнесс поднимает три сервиса (backend + webapp + website). Фактический прогон E2E требует
> Docker/Postgres + Chromium. Запуск: `bun run e2e:webapp` (или `bun run --cwd webapp e2e`).

## 8. Нефункциональные требования

- **Безопасность:** секреты (фид QuickDeal, токены) — только в env, не в репозитории; админ-роуты под
  `require-auth`; согласие 152-ФЗ обязательно и фиксируется (`consentAt`); публичные проекции настроек без секретов.
- **Антиспам:** honeypot + rate-limit по IP на публичном роуте лида; статус `SPAM` для ручной разметки.
- **Устойчивость:** валютный слой и импорт QuickDeal деградируют на последнее известное состояние при
  недоступности внешних источников; доставка лида в Telegram фоновая с ретраем (экран успеха не блокируется).
- **SEO:** индексируемые страницы в `website`; страница объекта сохраняется всегда, даже после «Продано»/`ARCHIVED`.
- **Локализация:** интерфейс на русском (мультиязычность — вне v1).
- **Дизайн:** пиксель-перфект по `design-reference/`; следование бренду и дизайн-системе.
