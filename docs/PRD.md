# PRD — DUNE Real Estate (dunestate.ru)

> Источник правды по продуктовым решениям. Технические детали реализации живут в коде;
> здесь — что и зачем мы строим, какие решения приняты и что остаётся за рамками.
> Архитектура/деплой/БД — в `docs/ARCHITECTURE.md`, `docs/DEPLOYMENT.md`, `docs/LOCAL_DATABASE.md`.

## 1. Продукт в одном абзаце

Сайт агентства недвижимости DUNE (город Грозный, домен `dunestate.ru`). Премиальная подача
плюс удобный поиск. Четыре направления продаж: **Новостройки** и **Вторичка** (Россия),
**Дубай** (ОАЭ) и **Саудовская Аравия**. Публичная часть — витрина с каталогом и заявками;
закрытая часть — админка для управления объектами, контентом главной и заявками. Аккаунтов
покупателей нет: избранное хранится в браузере, контакт с клиентом начинается с заявки.

Референсы тональности и UX: etagi.com, vladis.ru.

### Бренд
- Цвета: бордо `#48070d`, графит `#191919`, песок `#cbbba0`, светлый `#f6f6f6`.
- Шрифт: Montserrat.
- Логотип: знак-«ключ D» (буква D как головка ключа, звезда-искра, бородка), чистый SVG,
  масштабируется и перекрашивается через `currentColor`.
- Тема «дюны/песок» рифмуется с Дубаем и Саудовской Аравией.

## 2. Поверхности (где что живёт)

| Поверхность | Технология | Назначение |
|---|---|---|
| `website` | Astro (SSG/SSR) | Публичные SEO-страницы: главная, каталог, карточка объекта |
| `webapp` | React (CSR) | Админка за логином: объекты, контент главной, заявки, настройки |
| `backend` | Bun + Hono + Prisma/PostgreSQL | API, аутентификация, заявки, интеграции, курсы валют |
| `packages/contracts` | Zod | Общие схемы и типы между бэкендом и фронтами |

Маршрутизация по SEO, а не по привычке: всё, что должно индексироваться и красиво
расшариваться (главная, каталог, карточка), строится в `website`; админка без SEO — в `webapp`.

## 3. Что уже есть в коде (на момент написания)

Не переписывать — расширять.

- **Модель `Property`** (`backend/prisma/schema.prisma`) с направлениями `NEW | RESALE | DUBAI | SAUDI`,
  типами `APARTMENT | STUDIO | HOUSE | VILLA`, статусами `DRAFT | PUBLISHED | ARCHIVED | SOLD`,
  валютой `RUB | USD`, полями цены/площади/комнат/этажей, `complex`, `city`, `district`,
  `premium`, `installment`, `isNewBuilding`, `delivery`, `photos[]`, `badges[]`, `features[]`,
  `placeholderTone`.
- **Контракты объекта** (`packages/contracts/src/property.ts`): create/update/list, админ-листинг,
  сортировка (`newest | price_asc | price_desc | area_asc | area_desc`), пагинация (`page`/`limit`),
  фильтры (direction, type, currency, city, rooms, minPrice, maxPrice, premium, installment,
  isNewBuilding, q).
- **API объектов** (`backend/src/properties/*`): публичные `GET /api/properties`,
  `GET /api/properties/:slug` (только PUBLISHED) и админские `GET/POST/PATCH/DELETE /api/admin/properties`.
- **Аутентификация** (`backend/src/auth/*`): User + AuthSession, access/refresh-токены, сессии.
- **Storage** (`backend/src/storage/*`) — основа под загрузку фото.
- **Дизайн-прототип** (`design-reference/`): рабочий HTML/CSS/JS главной, каталога и карточки —
  визуальный эталон для пиксель-перфектной реализации в Astro/React.

## 4. Зафиксированные продуктовые решения

Приняты в ходе интейка с заказчиком. Это контракт по объёму.

1. **Направления.** Четыре: Новостройки (РФ), Вторичка (РФ), Дубай (ОАЭ), Саудовская Аравия.
2. **Объём v1.** Главная + каталог + карточка объекта + админка. Без личных кабинетов покупателей.
3. **Тональность.** Премиальная подача + удобный поиск.
4. **Демо-контент.** До получения реальных фото — брендовые плейсхолдеры с силуэтами городов
   (Грозный, Дубай, Эр-Рияд) и реалистичные демо-данные.
5. **Валюта — по направлению (см. §5).**
6. **Главная — фиксированные секции с редактируемым контентом (см. §6).** Без конструктора страниц.
7. **Избранное — локально в браузере** (`localStorage`), без аккаунтов и серверного хранения.
8. **Карта — точная точка объекта** по координатам, заданным в админке.
9. **Заявки — Telegram + БД сразу; Bitrix24 закладываем, включаем позже (см. §7).**
10. **Админка — один общий аккаунт**, без ролей. Публичной регистрации нет.
11. **Каталог — кнопка «Показать ещё»** (порционная подгрузка), не пагинация и не бесконечный скролл.
12. **Курс USD→₽ = курс ЦБ РФ + 2 ₽** (см. §5).
13. **Менеджер — по направлению** (задаётся в настройках, показывается на карточке объекта).
14. **Рассрочка** — маркер и калькулятор для новостроек.

## 5. Валюта и конвертация

Каждое направление имеет свою **базовую валюту хранения**:

| Направление | Базовая валюта (`Property.currency`) | Отображение цены |
|---|---|---|
| Новостройки (РФ) | `RUB` | `₽` |
| Вторичка (РФ) | `RUB` | `₽` |
| Дубай (ОАЭ) | `USD` | `$` основная + `AED` + `SAR` + `₽` (конвертация) |
| Саудовская Аравия | `USD` | `$` основная + `AED` + `SAR` + `₽` (конвертация) |

Правила:
- **Хранится одна цена** в базовой валюте направления. Конвертации — только для отображения.
- **AED и SAR привязаны к доллару** — фиксированные коэффициенты (константы в коде):
  `USD→AED ≈ 3.6725`, `USD→SAR ≈ 3.75`. Не требуют внешнего источника.
- **USD→RUB = курс ЦБ РФ + 2 ₽.** Курс ЦБ тянется автоматически (ежедневно, эндпоинт ЦБ РФ),
  к нему добавляется фиксированная надбавка 2 ₽; результат — для рублёвого эквивалента зарубежных
  объектов. Кешируется; при недоступности источника используется последнее известное значение.
- **Фильтр цены работает в валюте выбранного направления.** В каталоге одного направления слайдер
  цены — в его валюте (₽ для РФ, $ для зарубежных). В общем каталоге без выбранного направления
  числовой фильтр цены по умолчанию скрыт/неактивен (смешение валют недопустимо); уточняется при
  реализации, поведение по умолчанию — фильтровать только внутри направления.

**Гэп против текущего кода:** `Currency` enum (`RUB | USD`) хранения достаточно — AED/SAR не хранятся.
Нужно добавить: слой конвертации (константы + курс ЦБ), серверную задачу обновления курса,
поле настроек для надбавки (2 ₽, чтобы можно было поменять без релиза), отображение мультивалюты
в карточке и каталоге.

## 6. Главная

Фиксированный набор секций; редактируется только их **контент** (тексты, подписи, выбранные
объекты, изображения), не структура. Секции (по дизайн-прототипу):

1. **Hero** — заголовок, подзаголовок, CTA, фон (силуэт города/фото), опциональная карточка-объект.
   Поддержаны варианты композиции (полный/сплит/минимал) и выбор фона/акцента.
2. **Умный поиск** — табы по 4 направлениям, подменяющие город и счётчик объектов, переход в каталог
   с предзаполненными фильтрами.
3. **Плитки направлений** — крупные дуотон-плитки с силуэтами/фото, ведут в каталог направления.
4. **Подборка объектов** — лента с фильтром-табами (например, премиум/новостройки/по направлению).
5. **Рассрочка** — блок с рабочим калькулятором для новостроек.
6. **Форма заявки** — «оставить заявку» с экраном успеха.
7. **Футер** — контакты, направления, логотип.

**Гэп:** нужна модель/хранилище редактируемого контента главной (тексты секций, выбранные
подборки/плитки, ссылки на изображения) + экран редактирования в админке. Без билдера — плоский
набор полей под фиксированные секции.

## 7. Заявки (лиды) и интеграции

**Поток:** посетитель оставляет заявку (форма на главной, на карточке объекта, кнопка «оставить
заявку»). Заявка содержит контакт (имя, телефон, опц. e-mail/комментарий), источник (страница/объект,
направление), служебные метки времени.

**Доставка v1 (включается сразу):**
- **БД** — заявка сохраняется как запись (модель `Lead`), видна в админке (список + статус обработки).
- **Telegram** — уведомление в чат/группу менеджеров (через bot token + chat id из настроек).

**Bitrix24 — закладывается, включается позже:** код интеграции готовится (отправка лида во входящий
webhook Bitrix24, маппинг полей лида на поля сделки/лида CRM), но включается флагом, когда заказчик
предоставит URL/ключ входящего вебхука. До этого — только Telegram + БД.

**Гэп:** модели `Lead` нет — нужно добавить (схема + контракт + роуты + админ-список). Telegram-нотификатор
и Bitrix24-адаптер — новые модули бэкенда; Bitrix24 за флагом включения.

## 8. Карточка объекта

По дизайн-прототипу: галерея фото, ключевые характеристики (площадь, комнаты, этаж/этажность,
срок сдачи), описание, список «что входит» (`features`), цена с рассрочкой и мультивалютой (§5),
**карта с точной точкой объекта**, карточка менеджера направления, похожие объекты.

**Гэп:** на `Property` нужны координаты (`lat`/`lng`) + выбор точки на карте в админке; карта-заглушка
из прототипа заменяется реальной картой по координатам.

## 9. Каталог

Фильтры (направление, тип, комнаты, цена в валюте направления, площадь, рассрочка/премиум/новостройки),
сортировка, активные пилюли-чипы, счётчик результатов, пустое состояние. Открывается с предзаполненными
фильтрами по ссылкам направлений с главной. Подгрузка — **кнопка «Показать ещё»** поверх существующей
страничной пагинации API (`page`/`limit`): фронт инкрементит `page` и аккумулирует результаты.

Текущий контракт листинга это уже поддерживает — отдельный API-гэп минимален.

## 10. Админка

Один общий аккаунт (логин/пароль), без ролей и без публичной регистрации. Возможности:
- **Объекты** — CRUD, статус публикации (DRAFT/PUBLISHED/ARCHIVED/SOLD), фото, координаты, бейджи,
  фичи, флаги (премиум/рассрочка/новостройка), цена/валюта по направлению.
- **Контент главной** — редактирование текстов и выбора объектов/плиток фиксированных секций (§6).
- **Заявки** — список лидов из БД, статус обработки.
- **Настройки** — менеджеры по направлениям (имя, фото, телефон/контакт), Telegram (token + chat id),
  Bitrix24 (webhook URL + флаг включения), надбавка к курсу (по умолчанию 2 ₽).

**Гэп:** аутентификация в коде есть; нужны экраны админки (`webapp`), модели контента главной,
менеджеров и настроек, плюс админ-роуты для них.

## 11. Модель данных — что добавить

Поверх существующей `Property`:

- **`Property`**: `lat Float?`, `lng Float?` (точка на карте). Опционально `managerId` если когда-нибудь
  понадобится переопределение менеджера на уровне объекта — **в v1 не нужно** (менеджер по направлению).
- **`Lead`**: контакт (имя, телефон, опц. e-mail, комментарий), `source` (страница/тип формы),
  `propertyId?` (если заявка с карточки), `direction?`, `status` (NEW/IN_PROGRESS/DONE/SPAM),
  таймстемпы, флаги доставки (отправлено в Telegram / в Bitrix24).
- **`Manager`** (по направлению): direction, имя, фото, телефон/контакт; одна активная запись на направление.
- **`SiteSettings`** (singleton): Telegram token + chat id, Bitrix24 webhook URL + enabled-флаг,
  надбавка к курсу USD→₽, контент-блоки главной (или отдельная модель `HomeContent`).
- **`FxRate`** (кеш курса): база/котировка, значение, источник, время обновления.

Все изменения схемы — декларативно в `schema.prisma`, миграции генерируются штатным воркфлоу
(не писать SQL руками — см. CLAUDE.md «Prisma Migrations»).

## 12. За рамками v1 (phase 2+)

- Личные кабинеты покупателей, серверное избранное, сравнение объектов.
- Включение Bitrix24 (ждёт доступы), e-mail-уведомления о заявках.
- Ипотечный калькулятор, блоки «О компании»/«Отзывы», расширенный контент-менеджмент.
- Мультиязычность (сейчас интерфейс на русском).
- Автообновление курсов из нескольких источников, история курсов.

## 13. План реализации (фазы)

1. **Данные и контракты.** Добавить `lat/lng`, `Lead`, `Manager`, `SiteSettings`/`HomeContent`, `FxRate`
   в схему и `packages/contracts`; сгенерировать миграции и Prisma-клиент; обновить сид демо-данными
   по всем 4 направлениям.
2. **Бэкенд.** Валютный слой (константы AED/SAR + курс ЦБ+2₽ с кешем и cron), роуты лидов
   (+ Telegram-нотификатор, Bitrix24-адаптер за флагом), роуты менеджеров/настроек/контента главной.
3. **Website (Astro).** Главная (фикс. секции из контента), каталог («Показать ещё», фильтры по валюте
   направления, мультивалютные цены), карточка объекта (галерея, мультивалюта, карта по координатам,
   менеджер, похожие, форма заявки), избранное в `localStorage`.
4. **Webapp (админка).** Логин, CRUD объектов с картой-пикером и фото, редактор контента главной,
   список заявок, настройки (менеджеры, Telegram, Bitrix24-флаг, надбавка курса).
5. **Валидация.** E2E на критичные пути (создание/публикация объекта, отправка заявки → запись в БД +
   Telegram, фильтры каталога, переход с главной в каталог направления); контрактные тесты для лидов
   и валютного слоя; визуальная сверка с дизайн-прототипом.

## 14. Открытые вопросы / зависимости от заказчика

- Реальные фото объектов, городов и команды (сейчас — плейсхолдеры).
- Доступы Telegram (bot token, chat/group id) для включения уведомлений.
- Доступы Bitrix24 (URL/ключ входящего вебхука) — для включения CRM-интеграции позже.
- Подтверждение фиксированных коэффициентов AED/SAR и надбавки к курсу (по умолчанию +2 ₽).
- Поведение фильтра цены в «общем» каталоге без выбранного направления (по умолчанию — фильтр только
  внутри направления).
