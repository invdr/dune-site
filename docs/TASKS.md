## Решения обсуждения (v1)

Зафиксировано по итогам продуктового обсуждения. Имеет приоритет над более ранними допущениями
PRD там, где расходится (источник объектов, список типов).

### Источник объектов — QuickDeal (новое, не было в PRD)

- Объекты и менеджеры ведутся в CRM **QuickDeal**; сайт — **зеркало** через её **родной фид**
  (`/api/v6/feed/organisationObjects/{org}?format=quickDeal`). Не Яндекс-фид: тот теряет
  направление, `$`-цену, рассрочку, назначение земли, статус проекта (новостройка/вторичка).
- **Строгое зеркало:** поля из фида — read-only на сайте. Редактируемый «сайтовый слой»
  (`slug`/SEO, выбор в подборки главной, `badges`, премиум-кураторство, `placeholderTone`)
  переживает синхронизацию.
- Импортируем только объекты с `isSendToCompanySite` / `export=companySite`. Частота ~1 час.
- Идентичность/жизненный цикл: `externalId` = `feedId` (`QD_RS_*`), `source`, `syncedAt`.
  `status=sold` → на сайте «Продано» (страница живёт); пропал из фида → `ARCHIVED`.
  Страница объекта сохраняется всегда (SEO).
- Маппинг направления: `countryIsoCode RU` + вид «Квартира в новостройке» → `NEW`;
  `RU` + прочее → `RESALE`; `AE` → `DUBAI`; `SA` → `SAUDI`.

### Типы объектов (финал — под реальные виды QuickDeal)

- Набор: **Квартира, Дом (вкл. Коттедж), Таунхаус, Коммерция, Участок**.
- **Студия — не тип, а значение «комнат»** у квартир: Студия (`rooms=0`), 1-комн, 2-комн, …;
  фильтр комнат для жилья начинается со «Студии».
- `VILLA`/`STUDIO` из enum убрать, `PENTHOUSE` не вводить (нет в инвентаре).
- Категорийные фильтры: жильё (комнаты/этаж/площадь/срок сдачи/рассрочка/новостройка),
  участок (площадь в сотках/га, назначение земли, коммуникации, рассрочка),
  коммерция (площадь, вид помещения, этаж/этажность, рассрочка).

### Валюта

- Зарубеж: базовый `$` из `standardizedPrice` фида; AED/SAR — константы; `₽` — курс ЦБ + надбавка.
- Нет свежего курса → последний известный со знаком `≈`; полный холодный старт → `₽` скрыт.
  Округление `₽` крупное, со знаком `≈`.

### Заявки и менеджер

- v1: БД + Telegram (лид сперва в БД, экран успеха сразу, Telegram фоном с флагом/ретраем).
  Bitrix24 — позже, по доступам (за флагом).
- Антиспам: honeypot + щедрый rate-limit по IP, без капчи. Согласие 152-ФЗ обязательно (`consentAt`).
- Менеджер: персональный из `assigned` фида; нет — общий контакт компании.
- Подборки главной: пропавший/проданный объект тихо скрываем, добираем следующим.

- [x] Константы фиксированных коэффициентов: `USD→AED ≈ 3.6725`, `USD→SAR ≈ 3.75`.
- [x] Получение курса ЦБ РФ (ежедневно, эндпоинт ЦБ) + надбавка из настроек (по умолчанию +2 ₽) → `USD→RUB`.

## За рамками v1 (phase 2+, §12) — не делаем сейчас

- Личные кабинеты покупателей, серверное избранное, сравнение объектов.
- Полная страница политики конфиденциальности (в v1 — только обязательный чекбокс согласия).
- Включение Bitrix24 (ждёт доступы), e-mail-уведомления о заявках.
- Ипотечный калькулятор, блоки «О компании»/«Отзывы», расширенный контент-менеджмент.
- Мультиязычность (интерфейс на русском).
- Автообновление курсов из нескольких источников, история курсов.
